This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Via is a macOS desktop SSH local-port-forwarding manager. The UI is Vue 3 + TypeScript + Vite; everything real — config, encryption, SSH, listening sockets, runtime state, reconnect — lives in a Rust/Tauri 2 backend. All tunnels bind only to `127.0.0.1`.

Product docs (README, PRD) are written in Chinese; commit messages are in English. Scope is deliberately narrow: SSH Local Forwarding only (no remote/dynamic forwarding, no terminal/SFTP, no cross-platform). See `prd/via.md` for full product constraints and `docs/superpowers/plans/` + `docs/superpowers/specs/` for implementation plans and design specs.

## Commands

Prerequisites: Node 22+, Rust stable (edition 2024), Xcode CLT, and `cargo install tauri-cli --version "^2"`.

```bash
make install    # npm ci (pinned dependencies)
make dev        # Tauri dev window; Vite dev server on port 1420
make test       # full gate: vitest + vue-tsc typecheck + cargo fmt --check + clippy -D warnings + cargo test
make check      # fast static check: typecheck + cargo check + clippy -D warnings
make lint       # static check: prettier --check + vue-tsc typecheck + cargo fmt --check + clippy -D warnings
make build      # npm run build + cargo build
make format     # prettier (TS/Vue/JSON) + cargo fmt (Rust)
make package    # tauri build + local ad-hoc codesign into src-tauri/target/release/bundle/macos/
make clean      # remove dist/ and Rust target
```

Run one frontend test: `npx vitest run src/App.spec.ts` (specs are colocated as `*.spec.ts`). Run one Rust test: `cargo test --manifest-path src-tauri/Cargo.toml <test-name>` (integration tests live in `src-tauri/tests/`). Run `make test` before committing. After finishing development, also run `make format` (Prettier for TypeScript + `cargo fmt` for Rust), `make lint`, and `make build` before committing.

## Architecture

### Command surface (frontend ↔ backend contract)

The Rust functions in `src-tauri/src/commands/` are the entire IPC surface. The frontend never calls the backend directly — it goes through `createViaStore` (`src/stores/via.ts`), which wraps Tauri `invoke`/`listen` behind a `ViaBridge` interface that tests substitute with mocks.

Every capability requires edits in three places: the command is registered in `src-tauri/src/main.rs` via `tauri::generate_handler!`, and a matching permission appears in `src-tauri/permissions/autogenerated/` and `src-tauri/capabilities/default.json`.

Commands return errors as `format!("{e:?}")` Debug strings. The full error enum is `ViaError` (`src-tauri/src/domain/errors.rs`); the frontend maps known variants (host-key-required, port conflict, secret-store-locked, etc.) to translation keys.

Runtime state is pushed as `runtime-state` Tauri events containing per-rule `RuntimeRuleState` snapshots; the frontend also calls `poll_transports` on a 2-second interval to detect dead SSH transports.

### Runtime tunnel state machine (`services/tunnel_manager.rs`)

`TunnelManager` owns five maps: authenticated sessions (`Arc<dyn AuthenticatedSession>`), known rules, running `Forwarder`s, `manually_stopped` rule ids, and per-rule `TunnelState` (`stopped | starting | active | reconnecting | conflict | failed`).

Reconnect is implemented on **both** sides and must stay in sync:
- Backend: on a dropped transport, rules not manually stopped move to `reconnecting` and are restarted via `simulate_transport_drop`; backoff is `2^attempt` capped at 60s (`reconnect_delay_seconds`).
- Frontend: on a `reconnecting` event, `scheduleReconnect` in `stores/via.ts` re-invokes `connect_session` + `start_enabled_rules` with the same capped exponential backoff.

Manual stops are tracked on both sides (`manually_stopped` / `reconnectingSessions`) so a user stop is never revived by reconnect.

### Forwarding (`services/forwarder.rs`, `services/ssh_connector.rs`)

`SshConnector` authenticates via russh (password, or private key + optional passphrase from `SecretStore`), returning the session as `Arc<dyn AuthenticatedSession>` (trait: `open_direct_tcpip` / `is_closed`). `Forwarder` binds a `TcpListener` on `127.0.0.1:<local_port>`; each accepted connection opens an SSH `direct-tcpip` channel and `copy_bidirectional`s. A bind failure with `AddrInUse` maps to `ViaError::PortConflict`.

Host-key trust: `HostTrustStore` verifies fingerprints on connect. First-time keys surface `HostTrustRequired` (frontend shows an approval dialog, then `approve_host_key`); changed fingerprints surface `HostKeyChanged` and block the connection.

### Storage (`storage/`)

All state lives in a single SQLite DB at `<app_config_dir>/via.db`:

- `ConfigRepository` — groups/sessions/rules (each session's auth is JSON in `auth_json`), plus `app_preferences`. `save()` is delete-all-then-reinsert in one transaction; per-item deletes rely on foreign-key `ON DELETE CASCADE`. Import/export uses a separate `ExportConfig` DTO that strips all credentials.
- `SecretStore` — SSH passwords and key passphrases. Argon2-derived wrapping key + XChaCha20-Poly1305 AEAD, a wrapped data key, 10 one-time recovery codes, versioned metadata (v2, with v1→v2 migration on unlock). The master key lives in memory in `Zeroizing`; while the store is locked (`key = None`), `put()` keeps secrets only in an in-memory `ephemeral` map — nothing persists without a master password. `save_session_secret` encrypts and updates the auth reference in the same SQLite transaction.

### Frontend structure (`src/`)

- `App.vue` — orchestrator: gates the UI on secret-store state (setup → unlock/recover → workspace), drives settings, renders the session sidebar + tunnel grid.
- `stores/via.ts` — store factory (no Pinia); validators defensively reject malformed bridge payloads, so DTO shape changes fail tests rather than silently corrupt state.
- `types/via.ts` — DTOs shared with the backend (camelCase).
- `i18n/` — hand-rolled i18n (no vue-i18n): typed `TranslationKey` catalog (`catalog.ts`), `createI18n` with `{placeholder}` interpolation and system-language resolution. `zh-CN` and `en` catalogs must be kept in sync; translation keys are type-checked.
- `preferences/document.ts` — applies language/font-size/theme to `document.documentElement` (CSS variables, live `prefers-color-scheme` listener).
- Dialogs in `components/` each ship a colocated `*.spec.ts`; tests mock `@tauri-apps/*` with `vi.mock` + `vi.hoisted` and mount `App.vue` against an injected `i18n`.

## Conventions & invariants

- Serialization: Rust structs use `#[serde(rename_all = "camelCase")]`, enum tags `snake_case`. Match the frontend DTOs exactly — the store's validators reject mismatches.
- Security invariants: tunnels bind only to loopback; config export never contains passwords/passphrases/private keys; logs must not record secrets; host-key changes block connections.
- Commit messages use conventional-commit prefixes (`feat:`, `fix:`, `test:`, `docs:`) in English.
