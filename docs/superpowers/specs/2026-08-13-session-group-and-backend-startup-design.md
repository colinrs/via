# 会话分组与后端启动体验修复设计

## 目标

修复两个前端体验问题：新建 SSH 会话时可选择目标分组；Tauri 开发模式中 Rust 命令桥尚未就绪时，不向用户短暂显示错误状态。

## 范围与非范围

- 新建会话弹出轻量对话框，列出已有分组，要求选择一个分组后才创建会话。
- 当尚无分组时，保留现有行为：自动创建并使用“默认分组”。
- 启动时的状态栏区分“正在连接本地后端”和“重试耗尽后的连接失败”。
- 不修改 SQLite schema、会话 DTO、SSH 连接、隧道运行或持久化协议。

## 设计

### 创建会话

新增 `CreateSessionDialog`。侧边栏和空工作区的“新建 SSH 会话”只负责打开它。

对话框接收当前分组列表：

- 有分组时默认选择第一个分组，用户可在下拉框切换，确认后由 `App` 创建新会话并保存。
- 无分组时不要求选择；`App` 创建“默认分组”并将新会话归属其中。

保持会话默认字段不变。创建成功后选中新会话；保存失败时在状态栏显示现有保存失败提示。

### 后端初始化

`ViaStore` 暴露初始化状态：`idle`、`connecting`、`ready`、`failed`。`App` 在挂载时调用带有限次、短间隔重试的初始化逻辑。

- 重试期间状态栏显示“正在连接本地后端…”，不显示错误。
- `load_config` 成功且事件监听完成后，状态切换为 `ready`，状态栏显示现有的 `Rust backend: SQLite local mode`。
- 所有尝试失败后，状态切换为 `failed`，状态栏显示“无法连接本地后端”。

重试仅覆盖应用首次启动的初始化失败，不改变现有隧道断线重连策略。

## 测试

- 组件测试：有多个分组时，选择指定分组并确认，会把会话创建到该 `groupId`；无分组时仍会创建默认分组。
- Store 测试：首次 `load_config` 失败、后续成功时，初始化最终进入 `ready`；所有尝试失败时进入 `failed`。
- 现有前端测试、类型检查、Rust 格式、Clippy 和测试套件保持通过。
